# OctoAcme Project Management Docs

This repository contains the project management guidance used by OctoAcme to move from idea to delivery and closure. The lifecycle begins with initiation, where the team validates the business need, identifies stakeholders, defines measurable outcomes, and creates a lightweight project one-pager and initial plan. Once success criteria and priority are clear, work moves into planning, where the team builds a prioritized backlog, defines acceptance criteria, estimates scope, identifies dependencies, and creates a release timeline. Execution focuses on iterative delivery through a structured workflow with clear ownership, regular communication, and a visible project board so progress and blockers remain transparent.

The core principles of OctoAcme’s process are customer-first delivery, iterative work, clear ownership, data-informed decisions, and psychological safety. The project manager coordinates schedules, risks, and communications, while the product lead defines outcomes and prioritization. Developers and QA implement and validate the work, and stakeholders provide input and approvals. Communication is built around standups, weekly alignment, demos, and milestone updates so the team can surface dependencies and resolve risks early. Quality is reinforced through CI checks, tests, security scans, and manual QA where needed, with release gates that confirm acceptance criteria, smoke tests, rollback planning, and post-deployment verification.

At the end of each sprint or milestone, OctoAcme uses retrospectives and continuous improvement cycles to capture what went well, what should improve, and what action items need follow-up. This keeps the process grounded in evidence and learning instead of one-off fixes. The project management documentation in this folder is designed to support onboarding, standardize execution, and help teams apply consistent practices across all project work.

## How to Use These Docs

Use the overview to understand the system at a high level, then move to the relevant guide for your phase of work. For a new initiative, start with the initiation guide; during active delivery, use the execution and planning guidance; and for end-of-cycle work, consult the release and retrospective docs.
